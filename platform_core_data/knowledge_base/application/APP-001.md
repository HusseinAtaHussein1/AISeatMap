## Concept

**Operating Country is not the same entity as Country** — it is a separate Reference Data record
(Admin → Company → Operating Country) that wraps a Country with a Currency.

- Operating Country's own Add form fields: **Operating Country Name**, **Select Country** (the
  underlying Country), **Currency**.
- One Country can have **multiple Operating Countries** under it, each with a different Currency —
  this is *why* the two are separate entities: a single country's platform configuration sometimes
  needs to run in more than one currency context.
- This is why Branch's Add form (`discovery/Branch_Add.md`) shows both an **Operating Country\*** and
  a plain **Country** field side by side in its Location section — they are not redundant. Branch
  selects the Operating Country (Country + Currency pairing), not a bare Country.

## Source

User/business stakeholder explanation, 2026-07-18 (Egyptian Arabic, paraphrased above). Confirms and

operate, tied to Reference Data and Branch setup").

## How to Apply

- Reference Data dependency chain (`architecture.md`): `Region → Country → Currency → Operating
  Country → Branch → Agency` — read this as "Operating Country = Country × Currency," not a simple
  alias for Country.
- Any future Discovery/Test Design on the Operating Country screen itself should expect: a
  Select-Country dropdown, a Currency dropdown, and validation allowing (or requiring) uniqueness per
  Country+Currency pair rather than per Country alone — unconfirmed until that screen is actually
  discovered, but this is the expected shape going in.
- Any future Branch/Company test case referencing "Operating Country" should not treat it as
  interchangeable with "Country" in assertions or test data.
