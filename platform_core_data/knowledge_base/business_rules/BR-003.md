## Rule

Within Branch's **Supplier Routing** section (`discovery/Branch_Add.md`, [[BR-002]]), how you select a
supplier's **credential** differs by supplier type:

- **LCC supplier** (e.g. EgyptAir NDC) — a direct-connect Low-Cost-Carrier NDC integration where the
  supplier is effectively the airline itself. You select the supplier **and** its credential together,
  inline, in the same Supplier Routing row (top-level checkbox + dropdown).
- **GDS supplier** (e.g. Galileo) — a Global Distribution System aggregating multiple airlines behind
  one connection. At the top-level Supplier Routing row you only select/check the supplier itself —
  the actual **credential selection happens in a separate section further down** within the Branch
  module, not inline in that row.

## Status

Confirmed by user/business stakeholder, 2026-07-18.

## Observed Structure (screenshot, Branch Edit/BRN2, 2026-07-18)

Each Supplier Routing row is: **checkbox** (enable this supplier for the Branch) + **supplier name**
(e.g. `EgyptAirEgy`, `EgyptAirKSA`, `EgyptAirUAE`, `ElJazeeraV4`, `EmiratesNdc`, `Ethiopia`) + a
**"Select" dropdown** (the credential picker — e.g. `EgyptAirEgy`'s dropdown shows `EgyptAir Stg`
selected once checked) + a **Flight/Others** type label + a **Description** free-text field. Only
checked rows have their dropdown populated/enabled; unchecked rows show an empty `Select` placeholder.
This is the credential-selection UI referred to above — confirmed to sit **inside the Branch module
itself** (Branch → Edit/Add → Supplier Routing section), not the separate Master-module screen below.

## Explicitly out of scope for this rule

**Not to be confused with the Master-module "Credential Routes Filter" / "Supplier Credentials
(Restricted Airlines)" feature** (`PRD.md`, `resources/requirements/user_stories/Q2-CORE-WT1-T3002-066`
and `T3087`, already covered in RUN-20260710-001) — that is a separate White/Black-list route-based
airline filter, unrelated to this Branch-level supplier/credential selection. User explicitly
clarified 2026-07-18 to keep this rule scoped to what's inside the Branch module, not that other
feature.

## Source

User/business stakeholder explanation, 2026-07-18 (Egyptian Arabic, paraphrased above), plus a live

## How to Apply

- Do not assume Branch's Supplier Routing rows are structurally uniform — `Branch_Add.md`'s
  "checkbox + dropdown + description rows, one per configured supplier" observation holds for LCC
  rows, but a GDS row's dropdown is not necessarily the credential picker; the real credential
  selection for GDS suppliers lives in a separate Branch-module section not yet independently
  discovered/itemized.
- Any Discovery pass that itemizes Branch's Supplier Routing block for the first time (currently
  not itemized — see `Branch_Add.md` Coverage note, "~30 rows... not itemized individually") should
  capture both an LCC-type row and a GDS-type row separately, and locate/document the GDS credential
  section explicitly.
- Any future Test Design/Automation for Supplier Routing must branch its steps by supplier type
  (LCC vs GDS) rather than using one generic "select supplier + credential" flow for both.
