## Rule

GDS and LCC suppliers differ in **which airlines' flights they can return** in a search result, not
just in credential-selection UX ([[BR-003]]):

- **GDS supplier** (e.g. Galileo) aggregates and can return flights from **many different airlines**
  — a marketplace of carriers, not a single-airline feed. This can include an LCC's own flights too
  (if that LCC also distributes via GDS) — but those still surface as that airline's own "Air"
  segment; GDS is just the distribution channel, the operating carrier is still that specific airline.
- **LCC supplier** (e.g. EgyptAir NDC, direct-connect) normally returns flights **from itself only**.
  It is still possible for a single returned itinerary to be **multi-carrier** (spanning more than one
  airline, e.g. an interline/codeshare journey) where this LCC is one of the participating carriers —
  even on a direct single-airline connection.

## How to Apply

- **Corrects an over-simplified example in [[BR-002]]:** "if only EgyptAir NDC (LCC) is enabled on a
  Branch, a search should return EgyptAir flights only" holds for a pure single-carrier LCC result,
  but is not a universal rule — even that LCC-only scenario can legitimately include a multi-carrier
  itinerary where EgyptAir is one of several participating airlines. It is not a bug if such an
  itinerary appears.
- **Do not generalize BR-002's "supplier enabled → only that airline's results" assertion to GDS
  suppliers at all.** A GDS supplier enabled on a Branch is expected to return multiple airlines'
  flights by design — asserting "only airline X appears" against a GDS-sourced search would be a
  wrong test expectation, not a defect if it fails.
- Any Test Design for Flight Search result validation (scoped by Branch Supplier Routing, [[BR-002]])
  must branch its assertions by supplier type: LCC → expect predominantly one airline, allow
  multi-carrier itineraries naming that LCC as a participant; GDS → expect multiple airlines,
  validate scoping differently (e.g. via the Master-module Credential/Route filter rules, out of this
  rule's scope).
