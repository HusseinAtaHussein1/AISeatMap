## Execution Context

RUN-20260713-001 — `tests_SHAFT`, TC-AGENCY-001 full-form fix (Contract Start/End Date fields).

## What Happened

`p-calendar`'s underlying text input appeared to accept a scripted value assignment (Playwright's
`.fill()`, and a JS `element.value = ...` + `dispatchEvent` equivalent) — the value showed up
momentarily — but read back empty afterward, and the field stayed `ng-invalid`. SHAFT's `type()`
(which sends real per-character keystrokes, Selenium `sendKeys` semantics) worked correctly with no
special handling once this was understood; the failure mode only ever affected scripted/synthetic
value assignment, not real keystroke-based typing.

## General Pattern

**When a PrimeNG `p-calendar` (or any component with its own internal input-mask/parsing logic)
appears to accept a value but doesn't retain it, suspect the input mechanism, not the value format.**
A single scripted value assignment is insufficient — the component needs real, per-character
keystroke events to trigger its internal parsing. SHAFT's/Selenium's `sendKeys`-based `type()`
already does this; a `.fill()`-style API (common in other frameworks) does not, and needs an
explicit switch to character-by-character typing for this class of component.
