## Execution Context

RUN-20260713-001 — `tests_SHAFT`, TC-AGENCY-001 full-form fix (Phone No / Owner Phone / Sales
Contact Phone fields).

## What Happened

The phone fields use `ngx-intl-tel-input`, which renders its own country-flag selector (defaulting
to Egypt in this app) separately from the raw text input. Typing a literal international prefix
(`+201001234567`) into the text input is redundant with, and can conflict with, the component's own
country-code handling — the field's own `ng-invalid` state (with an accompanying "Please enter
valid phone number" message observed on at least one field) only cleared once the plain national
number (`1001234567`, no `+20` prefix) was typed instead.

## General Pattern

**When a phone field is wrapped by a dedicated international-phone-input component (recognizable
by its own flag/country selector rendered next to a plain `<input type="tel">`), type only the
national number — never a literal international prefix — since the component already tracks the
country separately and a redundant prefix can be misparsed as part of the number itself.**
