## Execution Context

RUN-20260713-001 — `tests_SHAFT`, TC-AGENCY-001 full-form fix (post-submit navigation check).

## What Happened

After clicking "Send For Approval" on a now-fully-valid form, checking the resulting URL
immediately (or after a short fixed `Thread.sleep()`) was itself a race: one run's own diagnostic
call (evaluating the Agency Name field's value as part of a failure message) threw
`NoSuchElementException` because the page *had* actually already navigated away from the Add form
by the time that diagnostic ran — moments after an assertion, evaluated slightly earlier, had
(incorrectly) read the still-on-the-Add-form URL as evidence of a blocked submission. A fixed delay
picked a number that was sometimes too short and gave an inconsistent result depending on exact
timing.

## General Pattern

**Never assert on a post-submit navigation/state change using a single fixed-delay check.** Poll
for the expected end state (e.g., "URL no longer contains `/add`") with a reasonable timeout
instead of sleeping a fixed duration and checking once — this is the same class of fix as REP-001
(Branch List row-count polling) and `SearchAgency_Page`'s own results-render poll, applied here to
post-submit navigation specifically.
