- **Finding ID:** FINDING-003
- **Title:** Branch's List screen auto-populates on load; Agency's (and possibly Staff's) does not, requiring an explicit "Search in grid" click
- **Category:** UX Issue
- **Severity:** Low
- **Severity Reason:** No criterion in the Severity Matrix (Critical/High/Medium) is matched — this is a usability inconsistency, not a blocked workflow or data-loss risk, so it defaults to Low per §5.4's fallback rule.
- **Confidence Score:** 90% — directly observed and reproduced (Agency confirmed empty-then-populated across two separate page visits this run); Branch's auto-load behavior was consistent across its own visit.
- **Evidence Category:** Direct Observation
- **Status:** Needs Human Review
- **Business Risk:** A user accustomed to Branch's behavior (data visible immediately) may believe Agency has zero records and not realize a "Search in grid" click is required — plausible support/confusion cost, especially since Agency's true record count (9,537) is large and important.
- **Technical Risk:** Automation scripts iterating "visit List screen → read grid" for all three modules cannot use one shared step — Agency (and possibly Staff) requires an explicit search action first, or assertions will incorrectly read "zero records."
- **Module:** Admin → Branch (contrast case), Agency (confirmed), Staff (suspected — see FINDING-005)
- **Workflow:** List screen initial load
- **Description:** Branch's List screen (`Branch_List.md`) shows 149 records immediately on navigation. Agency's List screen (`Agency_List.md`) shows an empty grid on the same navigation pattern, populating only after "Search in grid" is explicitly clicked (`agency_list.png` vs. `agency_list_both.png`).
- **Expected Behavior:** Not defined in the Project Context (no PRD); inferred user expectation is consistency across sibling Admin CRUD screens sharing the same visual pattern.
- **Actual Behavior:** Branch auto-loads; Agency requires an explicit search click to reveal the same class of data.
- **Steps to Reproduce:** Navigate to Admin → Branch (data visible immediately) vs. Admin → Agency → Agency (grid empty until "Search in grid" is clicked).
- **Investigation/Recovery Result:** Validation-category — no retry performed; this is deterministic UI behavior, reproduced by revisiting the screen.
- **Investigation Notes:** Not confirmed whether this is because Agency's default Status filter genuinely returns zero *without* an explicit query trigger (i.e., the component never auto-queries) versus Branch's component auto-querying on mount — a front-end implementation difference, unconfirmed without source access.
- **Root Cause Hypothesis:** The Agency (and Staff) list components may not fire an initial data query on mount, only on explicit filter-button click, while Branch's does. Confidence: 50% — plausible framework-level explanation, not confirmed.
- **Occurrence Count:** 1 (tracked here; Staff's identical-looking behavior is tracked separately as FINDING-005 since it could not be conclusively confirmed as the *same* cause)
- **Evidence Links:** `agency_list.png` (empty), `agency_list_both.png` (populated, 9,537 results), `branch_list.png` (populated on load, contrast case).
- **Recommendation:** Confirm with the product/dev team whether this is intentional (e.g., a performance guard against loading 9,537 rows by default) or an inconsistency to fix. Either way, Test Design/Automation must not assume a uniform "navigate → read grid" step across all three modules.
