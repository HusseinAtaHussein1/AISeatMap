1. Executive Summary

US-4222 describes updating an agency. We tested it against the real staging system, on a real agency record (AGN2 — Test Egypt), and the feature works: of the 37 test cases you approved, 31 passed. Agency details, owner details, payment settings, documents, the logo, product selection and the submit-for-approval workflow all behave as the story describes.

Two things need your attention. A file that is not a PDF is accepted and stored as an agency contract document — the system checks neither the contents nor even the file name extension, although the logo upload beside it does check both. And deselecting a product cannot be undone: re-selecting it demands supplier-credential details the agency never had, so the form will not save. We found the second one by doing it, which means one change is still outstanding on the record — the Flight product remains deselected on AGN2, and putting it back needs a decision from you.

Three cases could not be run at all, for one reason: the installation has a single login, so an update cannot be submitted by one person and approved by another. That is the separation the approval workflow exists to enforce, and it is the one part of US-4222 we cannot tell you anything about.

16 of the 53 designed cases were not authorized to run — you rejected them at review — so this report covers 69.8% of the designed suite.

3. Defect Register1High / P11Medium / P2
Defect · High · P1 · Workflow
Deselecting a product is irreversible through the UI, and it destroys the product's supplier-credential configuration. Re-selecting Flight renders a blank supplier-credential panel in which Manager Name and Supplier Credentials Description are mandatory, and the form refuses to save until both are filled — the agency has no values for either. The stored credential is still present in the grid and its selection checkbox is still ticked, so the association was never lost; the block is purely the empty panel. (TC-AGENCY-041 — the case itself PASSED)
Suspected Component: Select Product / supplier-credential panel on the Update Agency form
Layer: Frontend — the block is client-side form validation on a panel the client itself renders empty
Reproducibility: Always — four independent attempts, each refused with the same two Required markers: plain re-select and save; re-select with a wait for the section to repopulate; re-select with the stored credential row explicitly ticked; and clicking the stored row to load it into the panel
Regression: Unknown — no earlier execution of this case exists to compare against
Impact: An administrator who deselects a product by mistake cannot undo it. Restoring the product requires inventing supplier-credential details the agency never had, which replaces one wrong state with another, or a direct database correction. On a live agency this silently changes what the agency is able to sell.
Root cause (inferred, not established): The credential panel appears to be an "add a credential" form whose validators activate once the product group is marked dirty, rather than a view of the credential already attached. That would explain why the record saved normally for the whole run while the product selection was untouched, and refuses only after the selection is changed.
Confidence: High — reproduced four ways, with the refusal message located and attributed to two named fields each time

Defect · Medium · P2 · Validation
Agency contract documents are subject to no format validation whatsoever: not by content, and not even by file extension, since the file dialog is unrestricted. A 297-byte plain-text file with no %PDF header, named .pdf, was accepted silently, submitted, approved, and listed as an attached contract document after the agency was reopened. (TC-AGENCY-020 — Failed)
Suspected Component: Agency document upload (ndc-fg-file-input, input[name=docId])
Layer: Frontend and Backend — the browser accepted it with no filter and the server stored it, so neither layer validates
Reproducibility: Unable to confirm — observed once in this run. The single observation was clean and fully evidenced, but the standard for Always is at least two independent observations.
Regression: Unknown — no earlier execution of this case exists to compare against
Impact: Any file can be stored as an agency contract document provided it is named .pdf. A user who attaches the wrong file, or a corrupt one, receives no indication of the problem; the error surfaces later, when somebody opens the contract and finds it unreadable. Because the stored artefact is the evidence of the commercial agreement with the agency, the failure is discovered exactly when the document matters most.
Root cause (inferred, not established): The logo control constrains its file dialog with accept="image/*" and rejects a non-image at submit, while the document control declares no accept and produced no message. The most plausible explanation is that document format validation was simply never implemented, rather than implemented and bypassed.
Confidence: High that the behaviour is as described; the observation is direct and the stored result was re-read after reopening the record.
