## Notes

- The Playwright package was generated *before* the Reference Automation Project was registered and *before* the Login Test Case Validation Pass finalized the 8-case suite — it should not be treated as complete or current.
- `tests_SHAFT` was generated 2026-07-12 per a consolidated Decision Gate (Generate now / Target / Framework / Strategy, `agents/automation_agent.md` §33.1) answered once and not re-asked during that Stage 4 run.
- **RUN-20260712-002** re-asked the consolidated gate fresh and got the same Target/Framework, with Strategy = Continue `tests_SHAFT` — extended in place with Admin Branch/Agency/Staff assets. During this extension, the Reference Project's own `Agency` Add page objects (`AddAgencyCore_Page.java`, `AddAgency_Page.java`) were found stale/empty and NOT reused — see `platform_core_data/runs/RUN-20260712-002/automation/AutomationPlan_SHAFT.md` "Existing Assets."
- **RUN-20260713-001** further extended `tests_SHAFT` in place with Create Agency's full-form fix (TC-AGENCY-001) and Search Agency (TC-AGENCY-006, new). All 4 Agency tests confirmed passing 2026-07-13.
- **RUN-20260721-001** further extended `tests_SHAFT` in place with `AdminPages.Admin.Company.Role.Role_Page`/`Role_TC` (13 of 22 approved Role cases fully automated). `AdminMenu.java` extended additively (`openCompany()`/`openRole()`).
- **RUN-20260718-001** originally started a *second, independent* SHAFT package, `tests_SHAFT_Agency` (v3 Agency Test Design — Create/Search/Actions/Update), per the Strategy Decision Gate's then-available "start a new package" option — closing FINDING-007's open question on Agency's Actions column and Update screen, and logging FINDING-008 for cases whose described UI elements don't exist live. **This package no longer exists as a separate entity — see the 2026-07-24 consolidation entry below.**
- **2026-07-24 — Bootstrap Migration:** both SHAFT packages' code (as it stood after every extension above) was copied wholesale from their originating run folders into two separate Workspace Automation Baseline locations, via `platform_core/tools/automation_lifecycle/`. See `platform_core_data/runs/RUN-20260712-001/automation/automation_promotion.md` and `platform_core_data/runs/RUN-20260718-001/automation/automation_promotion.md` for the exact file-level bootstrap records.
- **2026-07-24 — Consolidation (one project per framework):** the platform's "multiple independent packages per framework" principle was reversed the same day (`.claude/skills/automation-skill/SKILL.md` §31.5, v8) in favor of exactly one authoritative project per framework. `tests_SHAFT_Agency` was folded into `tests_SHAFT` and deleted as a separate baseline:
  - **Page Objects** (`Agency_Page.java`, `SearchAgency_Page.java`): the `tests_SHAFT_Agency` versions were kept — confirmed via full diff to be pure supersets of the older ones (Update-screen support, extra search filters), zero regressions.
  - **`AgencyActions_Page.java`**: new, carried over as-is (no prior equivalent).
  - **Test classes**: the old combined `Agency_TC.java` (5 tests, TC-AGENCY-001/002/004/005/006) was replaced by the four newer split classes (`Agency_Create_TC`, `Agency_Search_TC`, `Agency_Update_TC`, `Agency_Actions_TC`, 42 tests total). A real diff found the newer classes were **not** a strict superset: TC-AGENCY-004 (an assertion-free diagnostic scenario — accepted as dropped, no real regression-detection value) and TC-AGENCY-005's specific BR-001 assertions (Arabic-script-stripped/Latin-CJK-preserved) were both missing from the new classes. Per explicit human decision, the BR-001 assertion pair was **ported forward** into `Agency_Create_TC.createAgency011_SalesContactArabicScriptReVerification`; the diagnostic-only TC-AGENCY-004 scenario was accepted as dropped.
  - **Scaffold files** (`LogIn_Page.java`, `CommonMethod.java`, `CredentialsLoader.java`, properties files): byte-identical between the two packages, no decision needed. `AdminMenu.java`: kept the `tests_SHAFT` version (superset — has Company/Role navigation the Agency-only package never needed). `agencyTestData.json`: kept the richer `tests_SHAFT_Agency` version (superset of fixtures; `unicodeContactPerson` value confirmed identical in both, so the ported BR-001 assertions hold unchanged).
  - `pom.xml` `artifactId` renamed `NDC_Login_Automation_Export` → `NDC_SHAFT_Automation`, since this is now the one project for the whole framework, not just Login.
  - `testng.xml`'s `Agency` test block now lists the four new classes in place of the old `Agency_TC`; `testng-agency-create-only.xml`/`testng-search-agency.xml` retargeted to the new classes' equivalent methods.
  - This consolidation is **not** an Automation Approval — the package remains `Pending Automation Approval` exactly as before; only its internal composition changed.
- Every future Stage 5 run for NDC must read this table (§31.1), state it plainly to the human, and ask the Framework Decision Gate (§31.2) before generating or modifying anything: extend the existing project for a framework, start a project for a framework that doesn't have one yet, or (rare, explicit) reset a framework's project from scratch.
