## Concept

Branch's **Payment Option** checkboxes (Add/Edit form, `discovery/Branch_Add.md`) are sourced from
**Master → Payment Gateway → Payment Method** (`/master/gateway/gateway-method`) — a master-data list
of individually named payment methods (observed 2026-07-18: 34 total entries, e.g. Cash, Wallet,
Credit Card, BANQUE MISR, Fawry, Isaiah, Filomena, Astrid, plus a long tail), each carrying its own
**Online/Offline** status and Edit action on that master screen.

This confirms and resolves what `Branch_Add.md` had only flagged as "Master-data-driven; not
itemized individually" — the actual source-of-truth screen is now known.

## Execution confirmation (2026-07-18)

Live-verified twice: (1) ad hoc against `.80` via `tools/browser_driver` (`vyujNmZrQH`); (2) as a
permanent SHAFT regression test (`Branch_TC.branchPaymentOptionReflectsMasterPaymentMethodStatus`)
against `.70` (`Isaiah`), per explicit user redirect to that environment — 1/1 Passed. Both confirm:
toggling a Payment Method from Online → Offline on the Master screen makes it disappear from Branch
BRN2's Payment Option list; toggling it back Online makes it reappear. Environment restored to its
original state immediately after in both cases. See `test_design/NDC_TestCases_Branch.md`
TC-BRANCH-008.

## Count discrepancy — resolved

`Branch_Add.md` observed **~26** Payment Option checkboxes on the Branch form, while the Payment
Method master list shows **34** entries. Confirmed 2026-07-18: the difference is **inactive (Offline)
payment methods** on the master list — Branch's Payment Option only surfaces methods currently marked
**Online**. Not independently re-counted to confirm the exact Online/Offline split matches 26/34
precisely, but the mechanism itself is confirmed.

## How to Apply

- Any Discovery/Test Design pass covering Branch's Payment Option section should treat Master →
  Payment Gateway → Payment Method as the field's data source, not an independent Branch-owned list.
- A functional test validating "toggling a Payment Method Offline on the Master screen removes/disables
  it as a Branch Payment Option choice" would directly test this relationship — not yet designed or
  automated.
- Resolves part of the Coverage Gap noted in `Branch_Add.md`'s Payment Options row ("not itemized
  individually") — the full 34-item enumeration lives on the Payment Method master screen, not
  duplicated here.
