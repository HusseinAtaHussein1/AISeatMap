## Rule

The Admin → Agency → Add Agency form's "Contact person" field (`#id-Contactperson`) does not
support Arabic-script (or, unconfirmed, possibly other non-Latin/non-CJK) characters. Arabic-script
input is silently stripped client-side before it ever reaches the Angular form control's underlying
model — no validation error, no truncation warning. Latin and CJK segments of a mixed-script value
are preserved intact.

## Status

**Confirmed by design** — 2026-07-18, user/business stakeholder confirmed the application does not
support Arabic-script input. Not an application defect; no escalation to the app team needed.

## Origin

Discovered as FINDING-006 (`runs/RUN-20260712-002/discovery/findings/FINDING-006_ContactPersonStripsArabicScript/metadata.md`),
originally misdiagnosed as a Selenium/ChromeDriver input-mechanism limitation, then re-diagnosed live
(RUN-20260713-001) as application-side by reproducing the strip via a raw JS `.value` assignment with
zero WebDriver involvement.

## How to Apply

- TC-AGENCY-005 (`test_design/NDC_TestCases_Agency.md`) asserts this directly: Arabic segment absent,
  CJK/Latin segments present. Not a Partially-Automatable/capture-only test — a real pass/fail check.
- Any other Contact-person-style field sharing this component elsewhere in Admin (not yet
  cross-checked) should be assumed to have the same behavior until independently verified.
- Do not re-raise this as a defect in future runs against this application.
