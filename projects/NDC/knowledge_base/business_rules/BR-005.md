## Rule

The Admin → Agency → Add Agency form's phone fields (Agency Master "Phone no.", Agency Owner
Details "Phone No.", Wonder Travel Sales Contact "Phone No.") expect the **national number only** —
no literal `+`-country-code prefix typed into the field itself. This holds even though User Story 3
("Create Agency")'s own Acceptance Criteria states "+ Phone country code" for all three phone rows.

## Status

**Confirmed by business/user decision** — 2026-07-18: "الفورم مش محتاجة +" ("the form doesn't need the
`+`"). Resolves the discrepancy flagged in `context/NDC_ProjectContext.v4.md` §6 #7 between this
User Story's stated Acceptance Criteria and the previously observed live behavior. The Acceptance
Criteria's "+ Phone country code" wording is treated as descriptive of the field's underlying
`ngx-intl-tel-input` component (which carries the country code via its own separate country
selector, not as literal typed text), not as a literal input-format requirement — not an application
defect, no escalation needed.

## How to Apply

- `TC-AGENCY-CREATE-007` (`runs/RUN-20260718-001/test_design/NDC_TestCases_Agency.md`) asserts this
  directly: a national-number value is accepted; a `+`-prefixed value is not required and is expected
  to be rejected/malformed by the component (country code is selected separately via the field's own
  country-code control, not typed inline).
- Applies to all three phone fields on this form (Agency Master, Owner Details, Sales Contact) — the
  same `ngx-intl-tel-input` component, per `REP-007`.
- Any other phone field elsewhere in Admin using the same component should be assumed to share this
  behavior until independently verified.
- Do not re-raise "+ prefix rejected" as a defect against this form in future runs.
