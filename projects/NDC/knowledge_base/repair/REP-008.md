## Execution Context

RUN-20260713-001 — `NDC_tests_SHAFT`, TC-AGENCY-001 full-form fix (Upload Document / Contract Dates
section, and Wonder Travel Sales Contact section).

## What Happened

Both the Document-attachment section and the Sales Contact section render one default row plus an
"Add" button, intended for adding *additional* optional entries beyond the first. Clicking "Add"
after filling the single default row does not "confirm" or "register" that row (it was already
live-bound) — it inserts a **second, empty row that is itself subject to the same required-field
validators**, which then blocks submission until either filled or removed. The correct action for
a single entry is to fill the default row and never touch "Add" at all.

## General Pattern

**Before clicking a form's "Add another entry" button for a repeatable section, confirm whether a
default entry already exists and is sufficient on its own.** A common false assumption is that
"Add" is required to commit/register the first entry — when instead it appends an additional,
independently-required entry that then blocks submission if left empty. Test by first submitting
with only the default entry filled; only click "Add" if that specifically indicates more than one
entry is needed.
