- **Title:** Branch/Agency/Staff creation submits to an approval queue ("Send For Approval"), not immediate activation — undocumented in Project Context
- **Category:** Requirement Gap
- **Severity:** N/A (Requirement Gap category default)
- **Severity Reason:** N/A category default.
- **Confidence Score:** 95% — directly observed on all three Add forms' submit button.
- **Evidence Category:** Direct Observation
- **Status:** Needs Human Review
- **Business Risk:** Test cases and automation that assume "Add → immediately Active/searchable" will be wrong; any created QA_SPIKE_ test record will sit in a Pending/unapproved state until a separate approval action is taken (approver/location unconfirmed this run).
- **Technical Risk:** Automation scripts that submit an Add form and then immediately assert the new record appears as "Active"/"Approved" in the List screen will fail — the correct assertion is that it appears with Approval Status = Pending (or similar), and a separate approval step (unconfirmed workflow, possibly "Registration Requests" under the Agency submenu) must run before the record is usable.

- **Workflow:** Add Branch / Add Agency / Add Staff
- **Description:** All three Add forms' submit button reads "Send For Approval" / "Send for Approval," not "Save" or "Add" — confirmed on `Branch_Add.md`, `Agency_Add.md`, `Staff_Add.md`. The Project Context (v3) did not anticipate this, since no PRD exists for this scope (Observation-based Spike).
- **Expected Behavior:** Not defined in the Project Context.
- **Actual Behavior:** Submit button explicitly labeled "Send For/for Approval" on all three forms.
- **Steps to Reproduce:** Open Admin → Branch/Agency/Staff → Add; observe the submit button label at the bottom of each form.
- **Investigation/Recovery Result:** Not applicable — this is a structural observation, no failure occurred.
- **Investigation Notes:** Not cross-checked against the "Registration Requests" screen under Agency's submenu (out of scope for this run per Project Context v3 §3) — that screen may be where these approvals are actioned; left as an Open Question rather than asserted.
- **Root Cause Hypothesis:** N/A — this is intended application workflow design, not a defect.
- **Occurrence Count:** 3 (Branch, Agency, and Staff Add forms all show the same pattern — recorded as one Finding per Duplicate Detection §5.9, since it's the same underlying condition across three screens)
- **Evidence Links:** `Branch_Add.md`, `branch_add.png`; `Agency_Add.md`, `agency_add.png`; `Staff_Add.md`, `staff_add.png`.

Automation should assert on Approval Status text, not just record existence.
