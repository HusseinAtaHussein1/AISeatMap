# FINDING-001

- **Finding ID:** FINDING-001
- **Title:** "Select All" checkbox described by the AC is absent from every observed sub-module tab in the live Add Role permission grid
- **Category:** Bug
- **Severity:** Medium
- **Severity Reason:** Matches "Validation issues · Business rule inconsistencies" — the permission-grid's own described convenience mechanism (bulk-select View/Edit/Approval for all rows) is missing, but every individual checkbox still works, so no core workflow is blocked (does not reach High).
- **Confidence Score:** 95%
- **Evidence Category:** Direct Observation (live browser automation, reproducible)
- **Status:** Needs Human Review
- **Business Risk:** An admin configuring a role with many permission rows (e.g., Admin → Company's 4-row grid, or modules with more rows) must tick View/Edit/Approval individually for every row rather than bulk-selecting, increasing configuration time and the chance of an accidental omission on a large role.
- **Technical Risk:** None identified beyond the missing UI control itself — no error, crash, or broken state observed; the underlying per-row checkboxes function normally.
- **Module:** Admin → Role Management → Create Role (`/admin/role/add`)
- **Workflow:** Add Role — permission-grid configuration
- **Description:** Project Context `ProjectContext_Role.md` §2.3 (`FR-ROLECRT-MOD-02`) states every sub-module must have a "Select All" checkbox that selects View/Edit/Approval for every row under it. Live observation of the Add Role screen's Dashboard tab (single "Display" row) and the Admin → Company tab (4-row grid: Operating Country, Role, Department, Advance Credit/Top Up) found no "Select All" checkbox, label, or control of any kind — confirmed both visually (screenshots) and via a full-page text search for "select all" (case-insensitive, 0 matches) and a DOM enumeration of all 189 checkboxes present on the Add Role page.
- **Expected Behavior:** Per `ProjectContext_Role.md` §2.3 `FR-ROLECRT-MOD-02`/`FR-ROLECRT-MOD-03`: "Each module must have smaller segments for sub-modules with an option to 'Select All' checkbox... Select all checkboxes (View, Edit, Approval) for all Rows 'Sub-Tabs'."
- **Actual Behavior:** No "Select All" checkbox is rendered anywhere on the Add Role screen (`/admin/role/add`), checked across both the Dashboard module tab and the Admin → Company sub-module tab. Only the per-row View/Edit/Approval checkboxes exist.
- **Steps to Reproduce:** 1) Log in as `odeysysadmin` (STG). 2) Navigate to Admin → Company → Role → Add Role (`/admin/role/add`). 3) Observe the Dashboard tab (default) — only a single "Display" row with View/Edit/Approve, no Select All. 4) Click the "Admin" module segment, then the "Company" sub-module tab — observe the 4-row grid (Operating Country/Role/Department/Advance Credit-Top Up), each with its own View/Edit/Approve, no Select All checkbox present anywhere in the tab header or grid.
- **Investigation/Recovery Result:** Not applicable — this is a Validation-class/static-absence observation (an element that isn't there), not a transient failure; no retry is meaningful per the Investigation & Recovery Engine's "no retry, deterministic" rule. Reproduced twice (two different tabs), same result both times.
- **Investigation Notes:** Searched the full page's rendered text for "select all" (case-insensitive) — 0 matches. Enumerated all 189 `input[type=checkbox]` elements on the page (all sub-module tabs render their rows into the DOM simultaneously, only visibility toggles per active tab) — none carry a "select all" role, label, or grouping semantics distinguishable from a per-row permission checkbox.
- **Occurrence Count:** 2 (Dashboard tab, Admin → Company tab — same underlying absence)
- **Evidence Links:** `company-tab-no-select-all.png` (Admin → Company tab, 4-row grid, no Select All visible), `dashboard-tab-no-select-all.png` (Dashboard tab, single row, no Select All visible). No console/network evidence collected — not applicable to a UI-absence observation per Smart Evidence Collection's Bug floor (screenshots + DOM inspection satisfy this case; no JS error was involved).
- **Recommendation:** Confirm with the Product Owner/development team whether "Select All" was descoped from this build, is planned for a later release, or is a genuine build defect — then update either the AC or the implementation accordingly. Until resolved, Test Design should not assert Select All's existence as a Covered requirement.
